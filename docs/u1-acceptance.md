## 实际界面流程

使用 `tests/u1_fixture_server.py --root "build-cache/U1 界面 合成验收"`，持久 Chrome 测试配置为 `D:/workspaces/pw-chrome-profile`。fixture 在导入前设置独立数据目录，候选和提取均不访问真实微信；加密界面使用模拟子进程／准备结果，加密算法另由上述合成数据库回归覆盖。

实际点击完成：

1. 从首次页面打开设置，列出两个明文账号和一个加密账号，选择并保存明文目录，密钥显示“无需”，直接进入身份步骤。
2. 查无命中后换备注查询；选择无公开微信号的条目，核对一次并保存；关闭设置后直接勾选会话并导入，得到 2 条合成消息。
3. 搜索同名昵称得到两个不同内部编号，默认不选首项；手工选择后保存成功。
4. 保存加密目录后，无密钥时通讯录准备和身份查询不可提前执行；点击主操作模拟提取，显示 2/2 通过；返回设置后主操作为准备通讯录，完成后可查找身份。
5. 展开已有密钥、保存文件路径，直接准备成功，无需重新提取。重启 fixture／刷新浏览器后保留配置，直接进入会话工作区。
6. 检查目录并勾选归属后改选另一候选：旧检查和勾选均清空，输入显示“未保存”，上方摘要继续指向实际保存目录。
7. 在 900×600 浏览器窗口检查身份、已有密钥及目录流程；摘要持续可见，设置内容可滚动，候选完整路径换行。保留截图于 `output/u1/`，仅含合成内容。
8. 用 `--port 8769 --fail-prepare-once` 注入一次密钥认证失败：任务显示准确失败与返回设置入口，设置主操作回到提取并显示原因；重新保存已有密钥后再次准备成功。已保存身份无需再次确认。启动不会把历史成功任务的“下一步”当成本次待办提示。

## 限制与验收过程中修正的问题

- 没有进行真实微信进程扫描、真实密钥提取或真实聊天导入；这是本批明确限制，不是待执行的 U1 验收项目。真实微信加密 WAL 的既有端到端待验状态保持。
- 浏览器加密链路为模拟子进程；不能将其称为真实微信提取成功。真实子进程编码和合成加密数据库另有隔离回归。
- 早先一轮 HTTP 回归的旧 fixture 在替换 Manager 前导入了默认目录；可能读取过默认账号及任务元数据，未执行真实提取、读取聊天正文／密钥或写入原档案。现已修正为导入前隔离，并用修正后的入口重跑。路径默认值测试仅在自己的环境上下文中移除数据目录覆盖。
- 一轮 HTTP 失败由交互 fixture 占用相同端口导致；已分开运行并重跑。一次 Windows 窗口读取超时后，按用户说明重新打开窗口，基础版和完整语音版均重新完成实际检查。
- 不把本机结果等同于干净 Windows／其他机器环境验收；本批不更新 ZIP，也未验证旧 ZIP 或新增兼容范围。无 U1 功能阻碍；U2—U5 继续按独立批次实施。
