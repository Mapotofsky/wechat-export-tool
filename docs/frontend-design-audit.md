# 前端设计审计与改进报告

审计日期：2026-10-28。审查基线：U3 提交 `8f461ec`，并与其前一个 U2 版本对比。

## 1. 结论与证据边界

当前前端将内部执行状态直接作为界面结构，缺少稳定的任务层级和信息取舍。U3 加入取消能力时，又在原任务面板上追加停止边界、发布状态和单位说明，加重了重复、跳变和技术信息外露。此前功能验收证明了一部分流程能够完成，不能证明这些流程具有良好的信息层级和视觉稳定性。

本报告依据用户提供的在线转写任务截图、当前前端源码、任务进度生产代码，以及 U3 与 U2 的提交差异。没有修改应用代码，也没有在本轮重新打开所有页面进行桌面验证。

- 截图可直接确认：任务标题层级错误、整体进度缺失、重复状态、无关提示、技术字段外露及名单挤占空间。
- 代码可确认：上述状态的生成与渲染条件，以及其他页面的控件、默认展示信息、加载和反馈逻辑。
- 交互风险或改进建议不是已完成的修复；键盘、不同窗口尺寸和完整流程需在实施时实际验证。
- 原始截图含私人聊天内容，不复制到仓库，不在报告中转录账号、联系人或消息。复现使用合成数据。

## 2. 用户目标与审查覆盖

| 用户流程 | 当前判断 | 证据 |
|---|---|---|
| 找会话、筛选与批量选择 | 工具入口偏多，信息和动作优先级不清 | `frontend/src/main.tsx`、`ConditionSelector.tsx`、用户截图 |
| 阅读与搜索 | 元信息重复，加载替换正文，搜索全文与片段叠加 | `main.tsx`、`style.css` |
| 分析与回查 | 能力齐全，但长页面、方法说明和范围重复增加负担；更新时存在旧结果归属不清风险 | `AnalysisWorkspace.tsx`、`AnalysisSettings.tsx` |
| 首次准备、账号与语音设置 | 长抽屉混合首次准备与日常维护，摘要重复 | `SetupSummary.tsx`、`main.tsx`、`VoiceWorkspace.tsx` |
| 任务执行、停止与重试 | 当前最严重的问题，整体任务被微小步骤覆盖 | 用户截图、`main.tsx`、`maintenance.py`、`voice_service.py` |
| 导出、隐藏、清理与退出 | 范围与恢复能力应保留，文案、反馈位置及动作命名需要整理 | `main.tsx`、`desktop.py` |

## 3. 任务面板：应首先修复

### T1. 单条在线请求覆盖批次进度

`voice_service.py` 的在线识别调用 `progress('正在发送或等待在线识别请求（最长 180 秒）', 0, 0)`；`maintenance.py` 用同一组 `stage/done/total` 保存任务状态；任务面板只在 `total > 0` 时显示进度条。

结果是单条语音进入网络等待后，原有批次计数被覆盖，进度条消失。下一次批次进度更新时又出现，用户难以持续判断整体完成情况。

改进：任务、主要阶段、阶段计数和当前条目的活动分别表达。等待一条语音响应时保留已有批次进度，只更新次级说明。准备时确实不知道总数，可以显示活动状态；不能制造百分比或预计剩余时间。不同阶段的字节数、数据库数、语音条数必须标明含义，不能让同一条未说明含义的进度条反复清零。

### T2. 标题与状态层级颠倒

页面直接把 `task.stage` 渲染为主标题，顶栏任务按钮也使用完整阶段文字。U3 又在原任务内容之前追加停止边界、发布状态与停止按钮。

结果是“等待在线请求”取代“语音转写”，用户先读到“安全边界”“逐条发布”，后面才看到任务内容；顶栏按钮也随小步骤改变宽度。

改进：任务名称稳定；主要阶段次之；当前条目的活动更低一级。顶栏只展示简短任务摘要。任务面板按任务名称、进度、当前活动、操作、结果组织，常用操作位置稳定。

### T3. 状态与技术说明重复

“任务正在执行”“进行中”“正在执行当前阶段”同时出现。正常运行时持续展示 `cancel_boundary`、`publication` 和最长等待秒数，这些信息通常不改变用户决策。

改进：保留一个明确状态。正常运行隐藏停止实现细节；用户点击停止后，说明当前为何仍在等待及哪些结果会保留。超时上限在超时错误或诊断中按需出现。正在停止、清理失败和已取消必须对应真实状态，不以删文案掩盖等待。

### T4. 后端结果字典直接成为界面

任务面板通过 `Object.entries(task.result)` 遍历所有标量字段；没有中文名称映射的字段直接显示原名，截图中出现 `device / online`。

改进：按任务类型明确选择展示项。用户需要知道新增成功、复用、失败及恢复动作；引擎、设备等按需进入详情。新增后端字段不应自动出现在主界面。

### T5. 范围名单挤占任务反馈

任务对象默认逐项展开，并常驻内部 username。会话较多时，结果和恢复操作被推到面板下方。

改进：默认展示账号与对象数量，完整名单可展开；同名核对时再显示内部身份。固定范围、完整核对和原范围重试继续保留。

## 4. 软件各区域的问题与改进

| 编号 | 区域 | 当前问题与代码依据 | 改进方向 |
|---|---|---|---|
| F1 | 全局反馈 | `error/notice` 同时渲染在主窗口与抽屉；通知没有按操作和面板隔离。旧提示会进入新面板 | 操作反馈优先在发生处显示；全局只保留影响整个软件的信息；结束或切换上下文时处理过期提示 |
| F2 | 范围预览 | 导入、转写、分析使用通用说明；零排除、零跳过与已有消息汇总也常驻 | 按动作突出真正相关的范围、条件和影响；异常或跳过存在时才展开说明，完整范围始终可核对 |
| F3 | 无关计数 | 操作预览用 `members.reduce(...)` 汇总当前档案消息数，它既不是新增导入量，也不是待转写量 | 删除该处汇总及仅为其展示服务的计算。不要为界面“完整”增加全账号消息汇总；保留有决策意义的查询、分析和删除计数 |
| F4 | 会话工具区 | 项目、管理、条件选择、搜索、类型、筛选、结果数、全选集中在列表上方 | 搜索和常用筛选直接可达；高级筛选与批量选择集中组织，减少对列表高度的占用 |
| F5 | 批量栏 | 替换关注范围、导入、转写、分析、导出同等排列；长期设置与临时操作混杂 | 高频内容操作优先；长期关注管理作为次级入口，替换动作明确影响；保留跨筛选选择与完整核对 |
| F6 | 消息展示 | 每条均显示类型、发送者和精确时间；搜索时全文与命中片段叠加；解释性页脚常驻 | 阅读与搜索分别组织摘要；普通文本类型不逐条重复；命中片段突出匹配位置，避免无意义复制全文；日期可分组，时间仍可查 |
| F7 | 阅读加载 | `loading` 时用整块加载文字替换原消息区 | 稳定阅读容器，按切换会话或分页提供相应局部反馈；若保留旧内容，必须标明其来源，不能误标为新范围 |
| F8 | 首次准备与设置 | 账号、目录、密钥、通讯录、身份、语音配置混在长抽屉；顶部摘要重复路径和身份 | 首次准备突出当前必要步骤；已有档案时展示日常维护；完整路径、诊断和高级设置按需展开 |
| F9 | 语音管理 | 会话名称全部铺开；任务反馈与任务面板两套实现；当前面板没有同等完整的停止入口 | 使用一致任务摘要，面板内即可看进度与停止；数量加可展开名单表达范围 |
| F10 | 空间回收 | 隐藏管理无条件显示“重试空间回收”按钮 | 存在未完成回收时才提供恢复入口；分别说明隐藏、删除提交和空间回收的实际结果 |
| F11 | 导出 | 范围、条件、排除说明较长；保存按钮统一显示“正在准备导出”，不足以区分等待保存位置与写入 | 默认突出对象、有效日期和格式；实际保存阶段反馈清楚，结束后就地提供打开结果；维持固定导出条件与退出保护 |
| F12 | 退出 | `desktop.py` 用“确定/取消”承载停止后退出/继续等待；最小化仅写在说明中 | 使用动作明确的选项；区分关闭抽屉与退出软件，说明当前等待的实际工作 |

计数取舍以用途为依据。筛选后的会话数量、搜索命中数、分页位置、分析分母、永久清理将删除的记录数有实际用途；与本次操作无关的全局消息汇总、重复总量、零值排除说明应收敛。删除展示不意味着删掉分析或数据保护所需的统计。

## 5. 分析区组织

现有筛选、下钻、代表摘录、完整命中、原文高亮和返回位置应保留。问题在于概览、构成、趋势、对比、节律、参与者、类型、词句、关联、关键词和片段连续组成长页面。

1. 按用户问题组织“活动变化”“词句与变化”“讨论片段”等入口，共享范围栏与证据区，减少无关滚动。
2. 图表、线索和回查优先；PMI、边界熵、Dice、排序公式、候选上限等方法信息放入对应详情。比较分母及指标含义仍须清楚。
3. 范围在阅读标题、分析栏和说明中重复，多会话名称直接连接成很长文本。收敛为一处有效范围摘要，名单可展开。
4. 异步更新保留旧 `data`，代码允许新范围标题与旧图表同时出现。必须明确旧结果所属范围及更新状态，或使用对应区域加载占位；不能把旧结果表现为新结果。

## 6. 视觉稳定性与可访问性

- 任务面板依靠通用段落、`h3`、名单与定义列表自然堆叠，缺少稳定的任务头、进度、操作和结果分区；通用间距在实时内容中造成大片空白。
- 应统一任务摘要、局部加载、操作结果、错误恢复与范围摘要的结构；保持紧凑列表与阅读区，不以大卡片或大量空白替代信息整理。
- 主抽屉的焦点循环只枚举部分元素，遗漏链接、`summary` 等可聚焦控件。需实际检查 Tab、Shift+Tab、Escape、焦点恢复及嵌套弹窗。
- 多处 `role="status"` 可能重复播报实时内容。播报应聚焦有意义的状态改变，避免每个小步骤都重复整段任务信息。
- 小窗口、长名称、大范围名单和底部批量栏应使用合成数据实测；代码存在响应式样式不能替代实测通过。

## 7. U3 责任归属与保留契约

U3 直接增加了停止边界、发布状态、单位说明等常驻内容，并加入在线请求微步骤，使同一组进度字段被覆盖的问题更频繁出现。

以 `stage` 作主标题、以 `total` 决定进度条有无、遍历结果字段、重复通知、无关消息汇总、长设置与长分析页等问题此前已有，不应全部归因于 U3。

本轮改进应保留：账号隔离；打开会话、临时选择与持续关注的独立语义；固定范围及重试；整次事务发布；旧档案可读；成功转写复用；真实停止与清理；子进程管理；隐藏、永久清理与空间回收恢复；导出保存及退出保护；完整查询分析和原文回查。前端表达可以调整，不能为了简化界面破坏这些契约。

## 8. 实施顺序与完成标准

### 第一优先：任务反馈

分开任务、主要阶段与当前活动；稳定真实进度与操作位置；去除正常运行时的超时上限、安全术语及技术字段；统一任务面板和语音管理的反馈。

验收：多条在线语音连续经历解码、请求、响应、复用和失败时，主任务名称稳定，批次计数不被单条步骤清空。未知总量如实反馈；停止、提交等待、清理失败和重试对应实际工作。无重复通知或过期成功提示。

### 第二优先：信息收敛

整理通知归属、范围预览、完整名单与计数；稳定顶栏，优化批量栏、准备设置、导出和退出选项。

验收：大量合成会话不会把任务进度和操作挤出可用区域；名单仍可完整核对；原范围重试不受后续选择影响；仅展示与操作相关的统计。

### 第三优先：工作区组织

整理阅读、搜索、分析导航、加载反馈与键盘行为。

验收：切换范围不误标旧结果；搜索、分析、上下文和返回保留原有范围与位置；常用桌面尺寸及窄窗口可用；键盘可完成主要动作。

### 验证与交付要求

使用隔离合成数据库、模拟工具和本地模拟在线服务；测试在导入 `web.app` 前设置临时数据目录。不读取或改动真实聊天、密钥及用户档案，不运行真实密钥提取或调用真实在线转写 API。

实际走通受影响的界面和桌面退出流程，并分别记录自动测试、浏览器交互、桌面及运行副本的证据。前端构建并按 README 同步已有基础版和完整语音版资源；中文空格路径和随包运行时验证实际入口。本轮无需重打发行 ZIP。

报告中的改进方向是实施依据，不是已验证结果；实施者须结合当时工作区核实证据并记录落实情况。完成后停止，不新增 U4/U5 或内容分析后续算法能力。
