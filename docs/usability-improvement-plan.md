## 1. 当前流程、主要阻断与证据口径

### 1.1 当前可用流程

1. 解压到可写目录，双击包内启动脚本；随包 Python 启动桌面宿主、FastAPI 和构建后的 React。工作区根入口运行 `dist` 的应用副本，默认数据仍在工作区，运行包需单独同步源码和静态资源。
2. 数据设置中选择或检测目录，检查结构，填账号标签并确认归属。目录必须直接包含 `contact/contact.db` 和有效消息分片；`inspect_directory()` 用通讯录文件头区分明文／加密。
3. 加密库需显式提取密钥或设置已有密钥，再准备通讯录；明文目录确认时已经准备通讯录，无需提密钥。身份支持微信号／内部 username 精确查询及昵称／备注检索，选择并核对后保存。
4. 关闭设置，选择会话，直接导入所选，或替换关注范围再更新关注；日常集合为源库对应消息表会话与本地归档的并集，再排除隐藏项；完整通讯录仅提供名称等信息。历史会话可按需刷新发现。当前会话、临时勾选、持续关注和项目成员互相独立。
5. 日常找到会话→阅读内展开搜索工具→三分区图表分析→按需看原文／前后文→导出。列表日期、消息查询和维护范围各自生效。维护时仍可读、导出此前发布的档案。

U1 已处理准备引导及提取诊断；U2 已补齐选择、范围核对、危险清理与恢复；U3 已支持安全停止和关窗退出。后续以这些能力为基础。分析已有三分区，剩余重点为分区内比较入口、数据相邻、滚动及原文返回；U4已补齐启动早期恢复和资源可见性。

### 1.2 已解决的实际案例

一次跨机提取曾反复失败，升级微信和管理员运行未解决。记录显示扫描到 24 个数据库、212 个节点、32 个候选，但无通过校验的密钥；随后更换为**当前登录账号对应的 `db_storage`，同样命令成功校验全部 24 个数据库**。此案例已解决，实际纠正动作及结果支持此前选用了不对应当前登录账号的数据库目录。

这个结论来自换目录后的成功对照。“有候选、零校验成功”本身不足以唯一定位原因；通用失败按3.3提供检查路径。目录归属按微信存储位置和用户选择核对，修改时间只作辅助信息。

## 3. U1：目录、身份、准备引导与密钥恢复（已实施）

U1-a、U1-b 已完成；实际回归、界面及运行入口结果见 [U1 验收记录](u1-acceptance.md)。U2、U3 分别见第4、5节；U4实施结果见第6节，U5剩余规格见第7节。

### 3.1 目录候选和绑定摘要

`candidate_db_dirs()` 返回全部候选，`auto_detect_db_dir()` 保留 CLI 单值行为；`/api/suggest-directory` 返回逐项检查后的候选集合。候选展示完整路径、账号子目录、明文／加密和消息分片数，不自动绑定首项。没有候选仍可选择或粘贴明文库／db_storage 根目录。

设置顶部显示账号标签、准备步骤和下一主操作；已保存完整源目录、账号子目录、本人 username／导出显示名从“已保存的目录与身份”按需展开。编辑目录标“未保存”，业务操作使用已保存目录。手工输入、原生选择、候选改选和已保存账号改选均清空旧结构检查、归属勾选和临时身份候选；保存时核对目录归属一次。目录帮助指向当前微信设置中的存储位置，目录名和时间不能自动证明归属。

目录保存后即可提取密钥或准备通讯录，无需先保存本人身份。明文目录保存时准备通讯录，直接进入身份选择。公开微信号和内部 username 精确查询保留；昵称／备注使用参数化字面子串查询，同名结果不自动选择。候选并列显示名称、微信号和 username。无微信号可按昵称／备注查找，无命中可换词、输入内部 username 或返回目录修改。保存仍验证所选 username 存在于当前准备库，并沿用一次身份核对。

### 3.2 基于状态的准备步骤

`Manager.status().setup` 根据已保存目录、密钥文件存在性、通讯录准备结果和本人身份计算下一步；HTTP 摘要补充已有可读档案。轮询只检查必要路径，不枚举全部源库或解析聊天正文。未增加绑定 pending 状态。

| 当前状态 | 主操作与恢复路径 |
|---|---|
| 未保存目录／源目录不可用 | 选择并检查目录；已有档案仍可阅读 |
| 加密、无密钥 | 提取密钥；也可展开“使用已有密钥”保存路径 |
| 加密、已有密钥 | 准备通讯录，准备时验证实际所需库，不强制重新提取 |
| 明文、通讯录已准备 | 查找并确认我的身份；密钥显示“无需” |
| 通讯录就绪、未保存身份 | 查找候选、核对显示名并保存 |
| 身份就绪 | 关闭设置，选择会话直接导入；持续关注可选 |
| 已有有效配置／重启 | 直接进入阅读，不重新确认目录或身份，不自动提取／导入 |
| 密钥文件无效、缺本次必要库或认证失败 | 保留旧档案；记录本次密钥准备错误，主操作回到提取，或重新保存已有密钥文件后准备 |
| 上次任务中断 | 保留任务范围及已发布结果，显式重新执行；不自动开始业务操作 |

前后端均检查操作必要条件。准备／发现无有效密钥路径时不可启动，身份查找需先准备通讯录；导入缺身份时在快照、解密之前拒绝。源文件结构检查仍在任务提交时执行，失败就地显示缺失项或系统错误码。后续按钮旁有当前缺失步骤说明；主操作可定位目录或身份输入。提取／准备任务可直接返回数据设置继续。源目录或密钥失效不遮断已有档案阅读。

`encrypted_sync.KeyPreparationError` 区分密钥文件格式、缺库和认证错误；其准备结果通过 `keys_error` 恢复下一步。重新保存密钥路径或成功提取会清除此结果，不要求额外归属或身份确认。

### 3.3 三项独立缺陷及提取诊断

换目录成功的实际案例仍作为恢复路径依据，不作为扫描缺陷的解释。已完成：

| 独立缺陷 | 当前修复 | U1历史隔离验证 |
|---|---|---|
| ≥500MiB 可读区域被整区排除 | 移除区域大小上限；Config 与 legacy 均按 2MiB 块读取，保留字符串／引用及最长 literal 所需重叠；部分读取不跨空洞拼接 | 模拟 WinAPI 枚举 501MiB 区域、稀疏大区域扫描；Config 名字和引用跨块并通过合成 HMAC；legacy literal 跨块 |
| 中文输出依赖 Windows 编码 | 工具入口固定 stdout/stderr 为 UTF-8；桌面捕获字节，诊断使用独立 UTF-8 JSON；tasklist 按 UTF-8／GBK／cp1252 解码 | 实际子进程在 cp1252／GBK／UTF-8 环境与中文空格目录均到达预期无数据库错误，无 UnicodeEncodeError |
| tasklist 内存字段解析中止提取 | 使用 CSV 解析，排序值只取数字；先检查退出码，空结果与命令失败分别处理 | 逗号、点、不换行空格格式均保留 PID；非零退出得到枚举失败 |

工具 `--diagnostics-output` 输出独立诊断 JSON。密钥仅进入密钥文件；Manager 只接收白名单中的阶段、异常类别、系统码、退出码、进程数、可读／跳过区域及字节数、读取失败数、名字／引用／候选数、实际库数、通过数和缺失库类别计数。不接收密钥、salt、内存原文、聊天、原始命令参数或路径，也不展示原 stdout/stderr。无诊断文件显示“工具未能完成诊断”，保留退出码，不猜测权限或账号原因。

| 实际证据 | 反馈与恢复 |
|---|---|
| 文件读取失败／结构不完整 | 显示具体缺失要求或系统码，保留输入以便修改目录 |
| tasklist 成功但无进程 | 未发现运行中的微信，启动并登录后重试 |
| tasklist 非零退出 | 进程列表执行失败，保留退出码 |
| OpenProcess 全部失败且包含拒绝访问码 | 系统拒绝读取进程，才建议适当权限重试 |
| 扫描可执行但无候选 | 未取得可校验候选，查看扫描覆盖和读取失败计数，核对账号存储目录 |
| 候选存在、零通过 | 候选未通过校验，核对当前账号目录；现有证据不唯一证明账号或权限问题 |
| 部分通过 | “部分完成”，显示 X/Y、缺失库类别；保存可用密钥，允许尝试准备通讯录，所需库缺失时明确恢复 |
| 全部通过 | 显示实际 X/Y，下一步准备通讯录 |
| 写结果失败／超时／编码错误 | 分别显示结果保存失败／提取超时／工具输出错误，按对应位置重试 |

旧诊断脚本未作为可运行入口沿用。U1在 `tests/test_setup.py`、`tests/test_background_processes.py` 重建隔离回归，统一入口 `scripts/verify_u1.py`；不扫描真实微信，不读取真实密钥和聊天。详细方法、运行产物及外部待验范围集中记录在验收文档。


## 4. U2：批量选择、范围和隐藏清理（已实现）

### 4.1 批量入口与条件

左侧“批量操作”打开全部选择面板，其中进入“按条件选择…”；底部批量栏优先导入、转写、分析、导出，持续关注管理按需展开。右键仍针对指针所指的单个会话，菜单头明确“此会话：名称”，不因目标已勾选而自动切换成N对象。右键不改变打开会话或临时选择。

“按条件选择…”默认作用于当前列表结果（包括虚拟列表未挂载的行），明确显示列表筛选条件及匹配数量；用户可显式切换到当前账号全部未隐藏会话。字段为类型、已归档／待导入、已归档消息数区间、最近已归档消息时间（例如90天前）。待导入的数量和时间为未知，不能作为0条／长期不活跃；单独“包含未知”默认关闭。日期按本机自然日并显示实际截止日期，不把已归档最后时间说成微信真实最近活跃。

条件预览后用“加入已选（新增X，总计N）”或“替换已选（N）”；替换明确提示将移除旧选择。反选仅对当前条件结果生效，结果外已选保持，显示“当前范围内反选”。切换搜索／类型／项目不清空已选。选择汇总与逐项名单使用“列表筛选外”，避免与已持久隐藏混淆。名单核对始终能看到全部对象、内部身份、总数及筛选外数。

`POST /api/selection-preview` 复用 `Archive.directory_contacts()` 的元数据及 `web/app.py:contacts()` 筛选口径，提供归档状态、消息数和最后消息时间条件；前端 `main.tsx` 组织条件和选择集合，不重新计算“时段有消息”等业务口径，不为选择而解析全部正文。`SessionList.tsx` 虚拟化保持，选择不依赖DOM；如匹配预览和应用期间档案更新，应用前刷新范围并显示差异，再由用户确认新范围。

### 4.2 执行范围契约

每次维护／清理／批量导出执行前，在当前抽屉或选择栏就地显示固定摘要与可展开名单。普通单会话可沿用可见按钮和对象名，不额外叠一串弹窗。提交后保存实际账号及去重对象快照；轮询和重试使用该快照，不根据当前勾选重算。`update_all` 在任务开始时记录实际未隐藏会话集合；执行和重试均传递该对象快照。

`Archive.source_sessions()` 从消息表目录及Name2Id／通讯录映射会话，`directory_contacts()` 优先读message_snapshot，否则decrypted_dir，补已有chats后排除隐藏；`maintenance_contacts()`直接复用。列表、待导入、条件选择、项目有效范围、更新全部、预览和提交共用此集合。仅通讯录项不新增，空消息表可映射对象可待导入，源已消失的归档保留；项目／关注配置保留，但操作取当前可用成员。隐藏管理补足隐藏对象信息，恢复后仍按同一集合判断：有源表可待导入，有档案可读，无源表且已清档案的不凭通讯录重现。重试仍固定原对象，不扩大为完整通讯录。修复不清理历史目录、聊天、转写或项目；集合断言见 `test_u2.py:test_large_directory_does_not_expand_conversations_or_execution`，历史数量只见[修复记录](session-scope-fix.md)。

| 操作 | 摘要与业务边界 |
|---|---|
| 列表筛选／条件选择 | “找到M个，共N个；当前已选K个，其中列表筛选外H个”；只改变列表或临时选择 |
| 导入所选／关注／全部／项目 | “账号A，N个会话的全部历史；不受消息日期、正文关键词影响”；列出未导入、已隐藏排除数量。不能用列表结果隐式替代关注／项目 |
| 普通转写／所选语音重识别 | 会话全历史与消息级targets分别说明；后者是明确例外，不扩展成全历史。复用成功转写／主动重做的区别在执行摘要中显示 |
| 分析 | 固定已导入会话和消息查询条件；待导入跳过名单及数量先显示，全部待导入时阻止并给导入入口。图表前置及原文按需打开继续保持 |
| 整段导出 | 固定会话集合＋消息日期，明确忽略正文关键词；按当前发布档案读取，多会话沿用ZIP |
| 命中导出 | 当前会话、关键词、日期／day、成功转写选项；上下文不计入。分析组合回查仍不是此导出范围 |

不给未扫描范围编造“约M条源消息”。空范围不扩大为全部；日期无命中、待导入、无可分析文字各自反馈。导出保持写完才提示“已保存”，浏览器只提示已交给下载。

`web/app.py:task()` 和 `Manager.submit()` 负责范围校验与固定；维护与分析预览使用 `POST /api/task-preview`，返回account_id、account_label、action、usernames、members、pending、excluded，转写另附voices计划，不启动任务。提交携带明确范围与account_id，若账号已切换则拒绝并要求刷新；不可用空数组表示all。项目预览复用 `group_scope()`，不另造一套项目成员含义。`main.tsx:previewOperation/executeOperation/previewGroup/analyzeSelected/exportData` 使用可见摘要中的对象快照；分析区的所选分析与语音管理的消息级重识别也进入共同核对入口。

### 4.3 隐藏与永久清理

保留当前默认：隐藏只排除列表、维护和项目操作，保留档案、关注集合、项目归属；恢复可立即读。不要建议用户为提高性能先永久清理大群。隐藏不等于取消关注；删除项目只删除归类。

普通隐藏面板：名单和N对象→默认“隐藏并保留档案”；“同时永久清理本地档案…”为按需展开选项。进入永久清理时展示来自服务端的实际消息数、全部转写数及其中成功数、导入基准会被清除；按钮改为危险样式“永久清理N个会话的本地档案”。明确“源库已消失的历史无法恢复；原媒体缺失则无法重做转写”。源库、共享解密库、密钥、模型、外部导出不在此删除范围。

隐藏会话管理的“清理所选档案…”已表达清理意图，可直接进入同一个危险确认面板并预选清理；不再额外要求先确认隐藏、再弹第二个确认。普通隐藏不要求输入，永久清理由这一处数量＋后果＋危险按钮完成明确确认，本轮不增加机械重复输入。已有隐藏N对象也显示“已隐藏；本次仅清理”，避免假装又执行一次隐藏。

`POST /api/hidden-preview`（显式account_id、usernames、purge），由 `Archive` 在同一只读快照统计消息和转写并校验已知对象；真正执行仍走 `save_hidden()`→`set_hidden()`。预览不是授权持久化，提交时在Manager锁下复核账号和维护状态；若本工具写入使范围或删除计数变化，返回最新摘要要求重新核对。当前串行维护约束保持，不新增哈希或通用修订框架。

删除消息、转写、来源关系、chats和相应会话基准与隐藏设置同事务发布；VACUUM／checkpoint在提交后。成功文案区分“档案已清理，空间回收完成”和“档案已清理，空间回收未完成，可重试”；后者不能误报全部失败，也不能声称数据可撤销。恢复已清理且仍有源消息表的会话显示待导入，重新导入只能取回源库仍有的数据。清理不复用维护取消按钮：当前SQLite删除提交和空间回收执行中阻止重复操作及退出，显示实际阶段；不可在删除已提交后声称取消保住原数据。

## 5. U3：长任务取消、进度和退出

### 5.1 最小任务状态/API

U3已实施，以下为当前契约；历史验证见[U3验收](u3-acceptance.md)，后续共享反馈及原生退出修正见[前端验收](frontend-improvement-acceptance.md)。维护仍单并发，`Manager`持有运行期取消信号、受控子进程句柄和明确发布阶段。`task.json` 持久化状态，不保存线程／进程句柄。

`POST /api/tasks/{id}/cancel` 请求携带account_id；校验活动任务ID及账号，只对所属当前任务申请取消。返回的“已接受取消请求”不是“已取消”。重复请求幂等；已结束任务返回其终态；其他ID／账号拒绝。`busy()` 包含running／cancelling／提交收尾与待重试资源清理，直到资源释放才允许新维护或切账号。

| 状态／字段 | 契约 |
|---|---|
| running → cancelling → cancelled | 点击后显示正在停止，等待当前工作及资源释放；清理完成才写cancelled和finished，前端显示已停止 |
| running → success／failed | 已发布成功即success；实际I/O／清理错误显示failed和已发布部分，不能遮成用户取消 |
| interrupted | 重启把running及cancelling标为中断，保留已发布结果说明，人工重试，不自动续跑 |
| stage、done、total、unit、activity | 分别表示主要阶段、已完成量、可知总量、单位及当前活动；未知total显示活动状态 |
| cancellable、cancel_boundary、publication | 可否取消、下一边界说明、未发布／已提交／部分逐条发布；已发布数量来自真实提交结果 |
| selected_usernames／voice_targets、account_id | 任务开始冻结；重试保持本次范围，不跟随当前列表或选择 |

### 5.2 安全边界按实际发布方式区分

| 任务阶段／改动位置 | 取消怎样生效 | 保留与清理 |
|---|---|---|
| 提取：`Manager.perform()`、工具扫描循环 | 监督本次工具及其下游进程；申请停止时终止受控进程组并等待退出，密钥写入前复核取消 | 未完成密钥文件不设为keys_file，旧有效密钥配置保留；清理本次私有输出。不能终止微信进程 |
| 快照／解密：`encrypted_sync.sync/stable_files/materialize/file_digest` | 文件复制和摘要分块检查；页面／WAL批次检查。异常必须退出context释放源库句柄及锁；SQLite quick_check等不可中断调用显示等待边界，不伪称已停 | 本次未发布代次可删除；原代次及所有配置指针引用的代次保留，不能把上次已发布快照当临时目录清掉 |
| 准备通讯录／发现：`Manager.perform()`、`Archive.prepare_directory()` | 在逐库读取边界及写入前检查；通讯录与相关快照指针同事务提交 | 取消在发布前不修改通讯录和指针；提交开始后等待完成，按实际结果显示。准备与导入各按其发布边界处理 |
| 导入：`Archive.update/_source_signatures/_update/_import_batch` | 签名块、消息batch、会话边界检查；用专用取消异常越出SQLite事务（不能被普通失败处理吞掉）。提交前在Manager锁内决定取消或进入不可取消提交阶段 | 提交前取消回滚整次消息、来源、元数据、成功基准和快照指针，旧档案可读。提交阶段完成后success，晚到取消不能把已发布结果标cancelled |
| 转写：`voice_service.transcribe/run_worker/recognize/recognize_online/request_online`、`local_asr.py:decode_audio` | 每条开始及识别结果保存前检查；监督worker及其FFmpeg子进程。在线请求先停止发送新条目，已发请求不能撤回，等待当前请求返回／超时再到边界；等待原因和超时可见 | 已逐条保存的成功结果及已记录结果保留；取消中的这一条不写伪造失败、不覆盖旧成功转写。显示已发布N条、剩余未处理；重试复用成功，明确重识别targets仍按主动重做契约 |

Windows Job Object已监督本任务工具、worker和下游FFmpeg进程树；关闭／超时同样等待树退出。保留后台隐藏参数与输出捕获，诊断入口仍可见。只取消本工具创建的子进程，不按进程名批量结束pythonw、微信或其他任务。任务终态写入前关闭文件和数据库连接；清理失败给出剩余临时资源及重试路径，不抢先允许退出造成半清理。

进度保留真实阶段计数：导入的会话进度与会话内已读消息分开，100%读完不等于已提交。未知总量显示活动状态，不提供虚构百分比或预计剩余时间。

### 5.3 关窗与其他任务规划衔接

主窗有维护任务时提供“继续使用／等待”“最小化继续处理”“停止后退出”；选择后者先申请取消，显示停止阶段，待子进程、事务和文件清理完成才退出服务。提交或永久清理等不可取消收尾阶段等待实际结果，不能强杀替代。

## 6. U4：启动恢复、能力、容量、日志与升级（已实施）

U4-a／b／c 已完成本机隔离验收，具体命令、合成数据、桌面结果与外部待验见 [U4 验收记录](u4-acceptance.md)。U1—U3、范围与语音跳过继续作为基础；本批未修改 U5。

### 6.1 实际数据位置与启动失败

`desktop.main()` 捕获数据／日志目录初始化、日志创建、实例锁、运行库、档案和窗口建立阶段的错误。`runtime_paths.check_writable()` 在实际目标目录一次创建、写入并删除小文件；Windows ACL 拒绝写入立即返回系统原因，不使用会反复重试文件名的 tempfile 创建器。只读程序配可写数据可运行；已有 `WECHAT_ARCHIVE_DATA_DIR` 始终生效，失败不换到新空目录。

错误对话框显示失败阶段、具体位置、系统原因及恢复动作，日志尚未创建也能恢复。缺运行库按 .NET／WebView2 和包内 prerequisites 提示处理；诊断 CMD 保留终端输出。启动 CMD 在缺少随包解释器时说明重新解压并保留原数据。

`InstanceLock` 用系统文件锁判定占用，首字节之后记录 PID 和程序位置。重复启动优先枚举该 PID 的已有窗口并恢复／激活；无法激活则显示所属 PID、程序、数据及日志位置。隔离无窗宿主已复现：持续无窗时核对没有维护或导出任务，再按该 PID 结束宿主并重启；不批量结束 Python。退出后即使锁文件仍在也可重新获取。

### 6.2 运行位置与语音能力

数据设置按需展开“程序与能力、数据位置及升级”。`runtime_paths.runtime_summary()` 与 `/api/runtime-summary` 提供显式 DTO：程序、数据、日志、包类型、Python、可取得的资源修订及更新时间和工具位置。发布资源同步记录资源修订（未提交时标工作区改动），不假称已有发行版本。

基础阅读、检索、分析、导出可独立使用。能力检查继续用 `/api/asr-status` 和 `voice_service.probe()`，只在用户点击时运行本地 worker；状态轮询不检测，打开设置不发送在线请求。本地语音需要运行时、Whisper、模型、SILK 与 FFmpeg；在线仍需 SILK／FFmpeg，无需模型或 GPU。检查结果和缺组件准备入口就地显示，语音配置继续使用原设置面板。

### 6.3 容量预检与磁盘满恢复

`preparation.plan()` 复用 `encrypted_sync.preparation_files()` 和 `Archive.voice_plan()`，预览、提交及实际准备共用文件选择。加密 prepare／discover／update 选择通讯录和消息实体分片；更新在所选会话有成功转写需复核时含媒体。转写选通讯录＋媒体、保留消息快照，人工跳过不进入识别；全部跳过不准备工具／媒体。

`/api/task-preview` 为准备、发现、导入／更新、转写返回按卷容量；前端先核对再执行，提交及执行前重新测量。DB／WAL 的实际 stat 大小构成已知必要复制量，当前保留档案／旧代次的实测占用单列并已反映在可用空间中。新快照与解密输出重叠按 DB 大小和 WAL 页估计，保守展示同存量，不用固定倍数。SQLite 导入临时表及语音临时文件单列实际目录所在卷；未知增长和不可取得的可用容量明确显示未知。

只有已知必要复制量超过可用量才阻止开始，显示目标卷、必要量、可用量及释放空间／明确数据位置的恢复路径。档案增长、SQLite WAL／临时写入、解码空间不能由该估计保证；运行中 OSError／SQLITE_FULL 进入任务失败反馈，旧档案与有效配置按原事务边界保留，成功转写仍逐条发布。任务记录本身写满不进入“运行中”；结束状态写满时保留内存结果并记录日志，重启按中断任务恢复。未发布新代次清理，旧代次不自动删除。

### 6.4 诊断、切号、升级

任务及资源摘要都有“复制本次诊断”，只复制现有结构化诊断、必要错误字段和运行位置，不读取整份日志。`NativeBridge.open_resource()` 只接受 data／logs；原 `open_path()` 继续限定最近导出。打开失败在原处保留原因，浏览器显示实际路径。

“目录与账号”提供已保存账号按 ID 切回入口；`Manager.switch()` 与 `/api/account-switch` 共用账号隔离、registry.active 和忙碌检查，不检查失效源目录。明确目标账号的独立档案及其他档案保留；新目录绑定仍经原归属确认和标签约束。切号保存离开时阅读位置，清空临时选择／上下文／分析范围并恢复目标账号阅读状态，维护或清理期间拒绝切号。

升级说明和打开实际数据目录入口同时提供。正常退出后，原地保留实际 local_data 替换程序及运行时；新解压目录通过 WECHAT_ARCHIVE_DATA_DIR 继续使用原数据。合成对照覆盖账号身份、消息、成功转写、人工跳过、关注／项目／隐藏、阅读状态和外部源／密钥／模型配置路径。资源清单和 ZIP 排除数据的规则保持；本批同步基础版及完整语音版应用资源，不重打 ZIP，不新增迁移／自动备份或旧代次清理平台。

## 7. U5：分析视图导航、滚动与返回

### 7.1 任务分组与入口

在现有“阅读／分析”入口内，保留**活动变化、词句与变化、讨论片段**三分区，剩余问题集中在分区内寻找比较、关联和返回来源，补充直接区域切换、相邻比较与位置恢复；同账号再次进入分析恢复上次分区及区域。区域切换只呈现当前内容。现有统计、完整范围和匹配口径保持。

| 现有分区 | 用户任务与保留内容 | 剩余改动 |

| 活动变化 | 概览、会话构成、时间分布、节律、参与者与类型；沿用每组六会话对比 | 时间／参与者提供直接区域入口；参与者趋势选择与排行相邻且直接可见；时期控件和两期总量移到下面的统一比较区域 |

需要共同判断的数据在同一视图中组织：对比时段、两期消息量、文字分母和提及变化相邻；关键词时间对比在专用区域内同时显示各关键词，沿用共同时间轴和纵轴尺度；参与者排行与所选趋势相邻。多关键词过多时分组展示，明确当前展示集合并能切换，不把各词散到不同区域。

折叠用于长说明、原文变体、嵌套原项、别名成员明细、更多结果和较少使用的参数。“两期提及变化”“关键词时间对比”“围绕表达的关联”“阅读片段”都有可见名称和入口；核心图表及功能入口不依赖逐个展开说明卡片。`AnalysisSettings` 的详细筛选、别名编辑和排除规则继续按需打开，相关视图展示已生效的简短摘要。

### 7.2 主要滚动区与导航高度

每个分析视图复用一个主要纵向滚动区。调整 `main.tsx` 的分析布局和 `style.css`：由现有 `.reading-scroll` 承载当前视图的纵向滚动，`AnalysisWorkspace` 内不再为排行或结果卡片设置固定高度的纵向滚动。会话列表仍有自身滚动边界；宽窗口中的证据阅读区可独立滚动，并有明确标题、边框和返回按钮。

`analysis.css` 中 `.rank-chart` 改为默认展示前12项与“展开其余／收起”，展开内容跟随主滚动区；词句复用 `termsPanel()` 前12项与按需展开方式，片段复用现有分页。单个完整排行仍很长时，在当前视图进入“完整列表”并分页，返回后恢复原位置，不另造卡片滚动窗。图表横向滚动（如热图）保留，参数弹窗有独立滚动不计作分析卡片嵌套。

现有sticky分区导航继续复用，滚动结果时仍可见。分析模式下合并范围摘要与已有消息日期／关键词摘要，保留一处修改入口；展开详细条件时占普通内容流，收起后显示已应用条件。不要同时固定多份会话名单、长说明、指标和工具栏。分区导航一行、共享摘要至多两行作为初始布局预算（约100px以内，指新增分析导航区域，不含应用顶栏）；沿用当前字号和点击尺寸，过长名单从“范围N个会话”按需展开。验收以实际可读空间为准，超预算先调整层级和重复信息。

在当前桌面最小窗口900×600及更窄的浏览器窗口检查：分区导航保持单行，必要时横向滚动并自动露出当前项，不能把核心入口都放进“更多”。正文卡片改为单列，关键词／参与者等控制可换行。窄窗打开原文时，证据阅读替换当前结果区域，顶部保留“返回〈视图名〉”和来源名称，使用同一主要纵向滚动区；返回恢复来源。宽窗侧栏在视口内独立阅读，主结果不因 `scrollIntoView()` 跳到页首；缩放或切换宽窄布局时保持当前来源与证据页。

### 7.3 共享查询、局部状态与就近返回

`AnalysisWorkspace` 当前已持续挂载并用hidden切分区，grain、趋势、关键词草稿、间隔等局部state已有，纯分区切换不发完整分析。继续由其持有同账号共享状态，补每区／区域位置和来源焦点，视图切换保留已有输入和查询。状态分为：

| 状态 | 保存与恢复规则 |
|---|---|
| 共享查询 | 账号、固定会话集合、消息日期、正文关键词、成功转写条件、有效分析筛选及其返回历史。三个分区及其区域共用；切分区／区域不清空、不重写日期或过滤条件 |
| 局部视图状态 | 时间粒度；会话对比分组；所选参与者；词句子类、所选表达、展开行及关联状态；对比当前区域、日期及草稿、关键词输入及已应用词组；片段间隔、页码；各完整列表页码。保留到用户修改或切换账号 |
| 位置 | 每个分区／区域及关键词对比／完整列表子区域分别记录主要滚动位置和最近操作项。保存于当前账号的前端内存；本批不新增服务端表或承诺跨重启恢复分析状态 |
| 证据返回位置 | 打开原文前记录分区、局部区域、来源稳定标识（词句／消息ID／片段username+first_id）、滚动位置和焦点。关闭后回到该项；原文页码／两期各自页码与原文滚动独立保存 |

纯视图切换先保存当前滚动，渲染目标内容后恢复其位置；首次访问该视图到顶部。共享查询实际变化时，重新计算结果并将受影响列表回到首批／首页，保持分区和仍适用的局部选择，显示本次查询摘要。无命中保留用户条件及清除入口；数据变化导致来源项消失时回到最近仍存在的列表位置。切账号清空旧账号的查询结果和证据状态，按现有账号隔离规则进入新账号。

词句点击将“选中表达”与“打开原文”分成明确动作：选择后高亮该行，紧邻列表的关联区显示“正在查看〈表达〉的关联”及结果；当前滚动无需跳到远处的关联标题。窄列可在所选行后呈现关联区，切换表达就近替换。点击关联中的“查看共同命中”才打开证据；`openTerm()` 相应改为选择表达，原文按钮沿用 `openEvidence()`。选择词句不改变正文关键词或全局分析筛选。

对比中的提及变化行沿用 `openChange()` 打开两期原文；点击片段“阅读片段命中”沿用 `openEvidence()`。上下文往返先恢复证据中的原命中页、页内位置与焦点，再返回分析来源，不把上下文扩大为分析筛选。`rememberPosition()/closeEvidence()` 从单个returnScroll扩展为上述来源记录；`context()/readPage()/readOther()` 保留证据侧各自位置，不覆盖结果位置。错误和加载反馈显示在触发的关联区、对比区或证据区，失败可在原处重试，已选项和输入保留。

键盘使用 `tablist/tab/tabpanel` 语义；左右键移动Tab焦点，Home/End到首尾，Enter或空格激活。Tab键进入当前面板，方向键移动Tab时不发分析请求。返回原文／完整列表后聚焦来源按钮；折叠按钮说明展开状态，固定导航不遮挡焦点。窄窗键盘聚焦的Tab自动进入可见区域。

### 7.5 任务验收与度量

用已有合成分析fixture扩充长参与者排行、不同词句、两期有效文字和多页片段。实施前在当前三分区代码相同数据及窗口记录基线：任务点击数（不计录入字符）、为寻找功能展开的区块数、累计纵向滚动距离／结果视口高度、返回后是否需要重新寻找、完整分析请求次数。

| 实际任务 | 目标路径与预期结果 |
|---|---|
| 找到两期提及变化 | 首次从任意分区至多两次导航激活：“词句与变化”→“时期与提及变化”，即见标题、时段、两期总量／文字分母。可按主滚动阅读列表，无需展开词句卡片。修改时段后，两期总量、分母与变化同步更新；打开两期原文再关闭，回到原行 |
| 进入关键词时间对比 | 从任意分区至多两次导航激活：“词句与变化”→“关键词时间对比”；若该区域为上次位置则直接恢复。输入词组并应用后，同区可对照各词曲线；切回时期与提及变化再进入，保留输入、已应用词组和位置 |
| 阅读片段后返回原位置 | “讨论片段”→翻到第二页→在页内滚动后“阅读片段命中”→查看前后文→返回命中→返回片段。原片段页码、间隔、展开状态和位置保留，焦点回到来源按钮，不回页首 |
| 选词查看关联及原文 | “词句与变化”→“词句与关联”→选择一个表达，在邻近位置看到加载／关联；查看共同命中再返回仍保留原词、子类与展开项，不需要长距离找关联区或来源行 |
| 带筛选跨视图比较 | 保持会话、日期、关键词、成功转写和发送者等筛选，连续切三分区及局部区域再切回；共享条件不变，各区恢复位置。纯切换及返回分析不增加完整分析请求 |
| 键盘与窄窗 | 在1366×860、900×600及680px宽浏览器中完成前三项；分区／区域可发现且可键盘激活，原文返回来源，轮滚结果不会被排行卡片截住；字号与现有阅读层级一致 |

通过条件：上述核心路径不需逐层展开来发现功能，两个指定对比任务达到表内导航步数；每个视图一个主要纵向滚动区，长列表可展开／分页；位置恢复后来源项可见、焦点正确且无需再次找回。比较同数据的导航步数和滚动距离，消除为跨越无关功能而进行的长距离滚动；记录实际结果，不要求所有图表或结果同屏。统计／分母／回查回归保持，完整分析请求数符合7.4，均满足后停止本批。

### 8.1 可复用验证入口与补充位置

所有新写入测试使用 `TemporaryDirectory` 合成源及档案。涉及 `web.app` 导入时先把 `WECHAT_ARCHIVE_DATA_DIR` 指向临时位置，避免模块级Manager创建真实档案。测试工具扫描时只用模拟WinAPI或测试进程自身内存；不用真实微信、真实密钥或聊天。U1、U2、U3 的已执行结果见各自验收记录。

- `tests/test_maintenance.py`：账号隔离、重启中断、失败回滚、身份与任务状态；已有setup、取消及发布回归按受影响路径复用。
- `tests/test_background_processes.py`：隐藏子进程、输出捕获、超时；已有密钥诊断、编码、树停止回归按需复用，保留不泄漏私有输出断言。
- `tests/test_selective_import.py`：选择性范围、空范围不导入全部、加密准备文件范围与按需媒体、失败后基准重试；已有取消前后基准与快照指针回归按需复用。
- `tests/test_projects.py`：隐藏、清理、恢复、项目完整范围；已有清理预览计数和提交复核回归按需复用。
- `tests/test_usability.py`、`test_search.py`、`test_export_invariants.py`、`test_web_http.py`：日期、查询、导出与HTTP；已有维护预览、跳过名单和切号拒绝回归按需复用。
- `tests/test_desktop.py`、`test_launcher.py`、`test_view_state.py`：可写路径、实例锁、保存、关闭、阅读恢复；`scripts/probe_upgrade.py` 复用合成升级思路，补转写和实际数据覆盖路径检查。
- `tests/ui_fixture_server.py` 可提供已准备合成会话；U1已有未准备／明文／加密配置态fixture可复用，不靠真实自动检测生成测试数据。
- U5沿用 `tests/test_analysis.py` 中两期分母、关键词序列、片段完整时间线和原文对账断言；`tests/test_analysis_matching.py` 保持现有匹配口径。扩充上述UI合成fixture，用浏览器交互记录分区、滚动、焦点、局部输入和网络请求；接口测试不替代这些导航验收。

后续按本批受影响流程验收：U4检查相应启动／恢复／切号／升级；U5检查7.5分析路径。验证右键与跨筛选、主操作的禁用原因、错误后的恢复位置、焦点和窄窗信息可见性；保持紧凑列表，图表前置，不用新增大片说明挤占阅读区。

U5额外执行7.5的分析任务，并在相同合成数据上记录改前／改后的导航点击、展开次数、滚动距离、返回位置及完整分析请求数。纯视图切换不触发统计；真实参数变更沿用当前完整统计，首屏展示和处理时间分别记录。

后续改入口／资源／子进程的批次需分别验证源码、已构建基础版／完整语音版、发行ZIP，实际双击中文空格路径入口；所用副本和发布标识写进验收记录。干净Windows、无预装运行库仍须单列，不能以接口成功或开发机结果替代。U5修改前端后按项目流程构建并核对实际运行副本。
