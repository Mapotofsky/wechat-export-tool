# 界面文案与信息层级验收

2026-11-01，在 U4 已实现的基础上调整用户可见文字及展示层级。未改变维护范围、停止条件、容量计算、分析算法或任务协议。

## 当前行为

- 容量预览先列各磁盘的预计新增占用和当前可用空间。新增占用标明部分估算；未知空间仍为未知，未估算完整时不宣布足够。复制、解密、保留副本和文件清单在明细中；确定不足仍阻止执行。
- 任务结果先显示新增／更新消息和转写结果。更新任务的 `reused` 是未变化或重复的来源记录，可能包括同一消息的多个来源，放入明细；转写任务的 `reused` 是保留的成功转写，显示“已有转写，未重复识别”。
- 停止及退出提示说明哪些结果保留、是否仍在等待及下一步操作。账号、会话、数量、失败原因、停止限制均保留。准备通讯录和发现会话说明名单用途，不把账号操作显示为空会话选择。
- 各阶段的真实计数直接显示，包括复制量、页数、帧数、数据库数、会话数及语音数。复制和解密页进度注明“当前文件”；总量未知时仍保留已处理数量。导入活动保留当前会话序号、读取来源记录及累计新增／更新数字，仅准确转述术语；不把来源记录数当作消息数。无活动内容时不占空行。
- 语音准备先显示可用状态、缺少组件及恢复入口，解释在线检查仅覆盖本机音频处理。打开或保存设置不会发起检查或转写，状态轮询不反复启动检测。
- 删除项目明确保留聊天记录；分析设置先解释开关效果和别名示例，精确匹配方法按需展开。
- 项目 AGENTS.md 合并了提示组织、常用准确表达及内部过程按需展示的规则。

## 阶段原值与渲染

后端不定义阶段文案映射，`Manager.status()` 不转换 `stage`／`failed_stage`。内部任务、接口返回与 `task.json` 使用相同原值。前端 `TaskFeedback.tsx` 的 `taskStageLabel()` 只在渲染时使用；任务面板、失败阶段、退出等待及进度无障碍标签共用它。复制诊断直接使用任务原值，不修改接收到的对象，也不增加任务展示协议。

逐项沿产生阶段的位置核实含义：

| 原阶段 | 显示 | 实际含义 |
| --- | --- | --- |
| 提交消息档案／提交通讯录／提交密钥 | 保存聊天记录／保存通讯录／保存密钥 | 已进入对应保存步骤；仍等待结束，不提前显示成功 |
| 读取微信进程并验证候选密钥 | 查找并验证密钥 | 查找候选并验证，不意味着已取得可用密钥 |
| 复制快照／稳定快照 | 复制聊天数据／准备聊天数据副本 | 复制及准备一致的源数据副本 |
| 解密主数据库页面／解密 WAL 页面 | 解密聊天文件／解密更新数据 | 分别处理主文件与更新记录 |
| 验证加密 WAL 提交边界 | 核对可读取的更新数据 | 查找有效更新范围，不代表档案已保存 |
| 解密与 WAL 合并 | 准备可读取的聊天数据 | 生成可读取数据，之后仍需导入 |
| 核对导入签名／复核明文源库签名 | 检查源文件变化／再次检查源文件 | 导入前后检查源文件，不另改成功基准 |
| 计算会话元数据 | 整理会话信息 | 整理会话计数等信息 |
| 提取与语音转写 | 处理语音转写 | 包含读取语音和保留已有成功文本，不暗示每条重新识别 |
| 检查本地识别工具／检查在线识别与音频工具 | 检查本地语音识别／检查语音转换工具 | 后者只检查本机音频处理，不验证在线服务 |
| 正在清理任务资源／资源清理完成 | 正在结束任务／临时文件已清理 | 前者尚未结束；后者仅说明清理结果，任务成败仍由状态表达 |

其他阶段保留原文字，包括“完成”“已停止”“部分密钥已保存”。“部分完成”仅用于成功且标记为部分完成的任务。总量未知不生成百分比；阶段转换不参与可停止判断或单位选择。
