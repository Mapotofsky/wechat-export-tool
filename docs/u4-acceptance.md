- 启动捕获实际数据／日志写入、日志文件、实例锁、运行库、服务及窗口错误；显示阶段、位置、系统原因和恢复动作，保留数据目录覆盖配置。

## U4-a：启动、实例与资源入口

| 场景 | 实际执行与结果 |
|---|---|
| 中文空格路径 | 通过包内 CMD 和新解压目录 CMD 启动桌面；源码及随包子进程正常，位置独立于 CWD |
| 只读程序＋可写数据 | `probe_u4_readonly.py` 对隔离程序目录设置真实拒写 ACL；先确认实际写入被拒绝，再通过 CMD 启动，覆盖到另一个数据目录，桌面／随包子进程成功。结束恢复 ACL |
| 不可写数据／日志 | `probe_u4_permissions.py` 对两个合成目标分别设置真实拒写 ACL。原生提示分别显示“初始化数据目录／初始化日志目录”、完整目标和 Permission denied；按 Enter 退出，返回码 1，ACL 恢复 |
| 日志创建／锁获取失败 | 单测分别注入日志文件创建和锁获取 PermissionError，进入对应阶段的恢复对话框，未越过异常捕获 |
| 路径被文件占用 | 实际启动分别用普通文件阻挡数据／日志目录，原生提示系统原因及数据目录恢复入口 |
| 缺运行库 | 隔离宿主注入 WebView2 缺失，实际原生提示显示 prerequisites 和诊断 CMD；未卸载本机运行库。原 .NET／WebView2 检查继续保留 |
| 同目录二次启动 | 通过实际 CMD 再启动基础版，已有主窗恢复，无第二个工作台实例；锁测试覆盖释放后重新获取 |
| 活宿主无窗 | 隔离 Pythonw 宿主持有实例锁但没有创建窗口，记录 PID 47460；二次启动提示该 PID、程序、数据和日志位置，没有把锁文件存在认作已死实例。以停止标记让该宿主释放后，同一目录 CMD 冒烟成功，未删除锁文件 |
| 资源与诊断 | 实际桌面展开摘要，打开本次数据和 logs 目录，资源管理器分别出现对应窗口。浏览器任务面板点击“复制本次诊断”后就地显示成功；单测确认 data／logs 专用边界及最近导出限制 |

真实拒写测试发现并修复了 Windows tempfile 在 ACL 拒绝时长时间尝试文件名的问题：启动探测改为一次独占创建、实际写入和删除，失败立即进入恢复对话框。
